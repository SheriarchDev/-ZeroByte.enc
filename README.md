## English

**ZeroByte.enc** is a lightweight, local and open-source file encryption utility built for Windows using Python, the PyQt6 framework, and the `cryptography` library.

The project is built around a simple philosophy: **your files should remain yours.** No cloud, no accounts, no telemetry — just local encryption with a transparent implementation.

ZeroByte.enc is designed with a strong focus on **data privacy, secure file handling, anti-forensics considerations, and protection of sensitive material in memory.**

### 🛡️ Security Features

* **Enterprise-Grade Encryption:** Uses the industry-standard **AES-256-GCM (Galois/Counter Mode)** authenticated encryption algorithm. Encrypted data is protected against unauthorized modification and corruption. An incorrect password or modified ciphertext causes authentication to fail rather than silently producing corrupted plaintext.

* **Hardened Key Derivation:** Master passwords are used to derive encryption keys through **PBKDF2-HMAC-SHA256** with a per-file random salt. The current Alpha release uses **100,000 iterations**. The strength of the resulting protection also depends on the entropy and quality of the user's password.

* **Memory Zeroing Protection:** Sensitive mutable buffers containing password material and cryptographic keys are explicitly overwritten with zeros after use. This is a best-effort memory protection mechanism; due to Python's memory-management model, it should not be interpreted as an absolute guarantee that every possible copy of sensitive data has disappeared from RAM.

* **Secure Shredding & `.zrb` Masking:** Before deleting the original file, ZeroByte.enc attempts to overwrite its contents with random data generated by `os.urandom`, followed by deletion. This provides an additional layer of protection against ordinary software-based file recovery. The `.zrb` extension keeps encrypted files separated from their original file types and does not expose the original filename extension.

* **Local-First Architecture:** ZeroByte.enc is designed to operate locally without accounts, cloud storage, telemetry, or an online service dependency. The source code is publicly available for independent inspection and auditing.

### 📦 Reproducible Builds & Integrity

The official Windows executable is compiled from the public source using the **Nuitka** compiler.

The SHA-256 checksum below allows users to verify that their downloaded executable has not been modified after publication.

| File           | SHA-256 Checksum                                                  |

| `zerobyte.exe` | `eb4068758819d8162c008174033d53c1ad3cd2ae3ae0a73e0271d4dbc67ad8e` |

To verify the checksum on Windows PowerShell:

```powershell

```

For users who require maximum transparency, the source code can also be inspected and the executable can be built independently.

### 🛡️ VirusTotal, SmartScreen & False Positives

When scanning `zerobyte.exe` through VirusTotal or launching it through Windows SmartScreen, users may encounter generic heuristic or machine-learning detections such as `!ml`.

This can happen because ZeroByte.enc performs operations that security software may associate with potentially unwanted or malicious behavior, including:

1. **File Encryption:** The application reads files, encrypts their contents and creates encrypted output files.
2. **Secure Deletion:** The application attempts to overwrite and remove original files after successful encryption.
3. **Executable Packaging:** Python applications compiled into standalone Windows binaries can have different binary characteristics from traditionally compiled applications.
4. **Code Signing:** An unsigned executable does not have an established publisher identity, which can contribute to SmartScreen reputation warnings.

A heuristic detection should not be automatically interpreted as proof of malware — but it also should not simply be ignored.

### 🔍 How to Verify the Application Yourself

**Do not rely on trust alone.**

* **Audit the Source:** The core source code is publicly available. Users can inspect the implementation for network activity, telemetry, unexpected behavior, or other concerns.

* **Build It Yourself:** Anyone can compile the project independently from the published source using the provided build instructions.

* **Verify the Hash:** Compare the SHA-256 hash of the downloaded executable with the checksum published in the release.

* **Review the Release:** For security-sensitive use, inspect the exact source revision and build process corresponding to the release you are installing.

Transparency is a feature.

## Русский

**ZeroByte.enc** — это легковесная, локальная утилита с открытым исходным кодом для шифрования файлов на Windows, разработанная на базе Python, графического фреймворка PyQt6 и библиотеки `cryptography`.

Проект построен вокруг простой идеи: **ваши файлы должны оставаться вашими.** Никаких облаков, аккаунтов и телеметрии — только локальное шифрование и прозрачная реализация.

ZeroByte.enc создан с особым вниманием к **приватности данных, безопасной обработке файлов, принципам Anti-Forensics и защите чувствительных данных в оперативной памяти.**

### 🛡️ Особенности Безопасности

* **Enterprise-уровень шифрования:** Используется промышленный стандарт **AES-256-GCM (Galois/Counter Mode)** — аутентифицированный алгоритм симметричного шифрования. Зашифрованные данные защищены от несанкционированной модификации и повреждения. Неверный пароль или изменение ciphertext приводит к ошибке аутентификации, а не к незаметной выдаче повреждённых данных.

* **Усиленная деривация ключей:** Мастер-пароли используются для получения ключей шифрования через **PBKDF2-HMAC-SHA256** с уникальной случайной солью для каждого файла. Текущая Alpha-версия использует **100 000 итераций**. Фактическая устойчивость к перебору также напрямую зависит от энтропии и качества выбранного пользователем пароля.

* **Защита оперативной памяти (Memory Zeroing):** Чувствительные изменяемые буферы, содержащие парольный материал и криптографические ключи, явно перезаписываются нулями после использования. Это механизм защиты по принципу best-effort; из-за особенностей управления памятью Python он не должен рассматриваться как абсолютная гарантия удаления каждой возможной копии чувствительных данных из RAM.

* **Secure Shredding и маскировка `.zrb`:** Перед удалением исходного файла ZeroByte.enc пытается перезаписать его содержимое случайными данными, полученными через `os.urandom`, после чего удаляет файл. Это создаёт дополнительный барьер против обычного программного восстановления удалённых файлов. Расширение `.zrb` отделяет зашифрованные файлы от их исходных типов и не раскрывает исходное расширение файла.

* **Локальная архитектура:** ZeroByte.enc рассчитан на локальную работу без аккаунтов, облачного хранилища, телеметрии и зависимости от онлайн-сервисов. Исходный код проекта открыт для независимого изучения и аудита.

### 🛡️ VirusTotal, SmartScreen & False Positives

При проверке `zerobyte.exe` через VirusTotal или при запуске через Windows SmartScreen пользователь может столкнуться с эвристическими или Machine Learning-детектами, например `!ml`.

Это может происходить из-за поведения, которое системы автоматической защиты могут ассоциировать с потенциально нежелательной или вредоносной активностью:

1. **Шифрование файлов:** программа читает файлы, шифрует их содержимое и создаёт зашифрованные файлы.
2. **Безопасное удаление:** программа пытается перезаписать и удалить исходный файл после успешного завершения шифрования.
3. **Особенности упаковки:** приложения Python, собранные в самостоятельные Windows-бинарники, могут иметь структуру, отличающуюся от традиционно скомпилированных программ.
4. **Отсутствие цифровой подписи:** неподписанный исполняемый файл не имеет подтверждённой издательской идентичности, что может влиять на репутацию приложения в Windows SmartScreen.

Эвристический детект сам по себе не является автоматическим доказательством наличия вредоносного кода — но его также не следует просто игнорировать.

### 🔍 Как самостоятельно проверить приложение

**Не обязательно верить разработчику на слово.**

* **Аудит исходного кода:** исходный код проекта открыт. Пользователь может самостоятельно проверить его на наличие сетевой активности, телеметрии, неожиданных действий и других потенциальных проблем.

* **Самостоятельная сборка:** проект можно независимо собрать из опубликованного исходного кода согласно инструкции по сборке.

* **Проверка хэша:** сравните SHA-256 скачанного `zerobyte.exe` с контрольной суммой, опубликованной в релизе.

* **Проверка релиза:** при использовании для действительно важных данных рекомендуется проверять конкретную ревизию исходного кода и процесс сборки, соответствующие устанавливаемому релизу.

**Прозрачность — это часть безопасности.**
